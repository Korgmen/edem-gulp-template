# Полезные советы

## <h2 id="no-ua-sniffing">Как обойтись без определения браузера и системы</h2>

Определять браузер или устройство по строке user-agent ненадёжно: она не соответствует реальному устройству или браузеру *(iPad с iPadOS представляется как `Macintosh`, Chrome на iOS — как Safari, Android содержит `Linux`)*, а знать почти всегда нужно не название браузера, а конкретную возможность — есть ли мышь, поддерживается ли свойство, занимает ли скроллбар место. На эти вопросы CSS отвечает сам.

### Мышь или палец: `@media (hover)` и `(pointer)`

Самая частая причина, по которой заводили классы устройств, — отделить десктоп от сенсорных экранов. Для этого есть медиа-функции:

```scss
// Наведение — только там, где есть настоящее наведение.
// На телефоне hover «залипает» после тапа, поэтому такие эффекты туда пускать не нужно
@media (hover: hover) {
	.card:hover .card__overlay {
		opacity: 1;
	}
}

// Грубый указатель — палец. Увеличиваем зону нажатия
@media (pointer: coarse) {
	.button {
		min-height: rem(48);
	}
}
```

`hover` отвечает на вопрос «может ли пользователь навести курсор», `pointer` — «насколько точен его указатель» *(`fine` — мышь или стилус, `coarse` — палец)*. Ноутбук с сенсорным экраном сообщит об этом сам, а user-agent — нет.

Важная деталь: открытие по `:hover` стоит **дополнять** фокусом, а не заменять им. Так компонент остаётся доступным с клавиатуры — именно так сделаны [тултипы](js.md#tooltips) в шаблоне.

### Высота экрана на мобильных: `dvh`, `svh`, `lvh`

Частый повод для определения устройства — блок на весь экран, который «прыгает» в мобильном браузере из-за исчезающей адресной строки. Для этого есть единицы, которые учитывают панели браузера:

```scss
.promo {
	min-height: 100dvh; // dynamic — подстраивается под текущее состояние панелей
	// 100svh — минимальная высота (панели раскрыты), 100lvh — максимальная (панели скрыты)
}
```

### Полоса прокрутки: `scrollbar-gutter`

Ещё один популярный случай — Windows против macOS: в Windows скроллбар занимает место, а в macOS он оверлейный и контент от него не сдвигается. Решение — одна строка, которая уже стоит в `base/null.scss`:

```scss
html {
	scrollbar-gutter: stable; // место под скроллбар резервируется всегда, контент не дёргается
}
```

Если всё же нужна точная ширина в пикселях — её считает модуль [calcScrollbarWidth](js.md#calcScrollbarWidth) и кладёт в переменную `--scrollbar-width`.

### Поддержка возможности: `@supports`

`@supports` проверяет, **понимает ли браузер конкретное объявление** — не устройство и не название браузера. Это правильный инструмент, когда вы применяете что-то новое и хотите запасной вариант:

```scss
// Обычная сетка как запасной вариант
.gallery {
	display: flex;
	flex-wrap: wrap;
}

// И masonry там, где он уже есть
@supports (grid-template-rows: masonry) {
	.gallery {
		display: grid;
		grid-template-rows: masonry;
	}
}
```

Проверять можно и селекторы — например, есть ли у браузера псевдоэлемент для анимации спойлеров:

```scss
@supports selector(::details-content) {
	// анимация раскрытия
}
```

Условия комбинируются через `not`, `and` и `or`:

```scss
@supports not (animation-timeline: view()) {
	// оформление для браузеров без scroll-driven анимаций
}
```

В JS у этой проверки есть двойник — `CSS.supports()`. Шаблон использует его, чтобы не грузить лишние 60 КБ полифила там, где он не нужен *(см. `src/js/modules/index.js`)*:

```js
if (!CSS.supports('animation-timeline: view()')) {
	await import('../libs/scroll-timeline.js');
}
```

#### ❗️ПРИМЕЧАНИЕ
У `@supports` есть ограничение: он проверяет, что браузер **разобрал** объявление, а не что реализовал его без багов. Свойство может поддерживаться и при этом работать криво — как раз из-за таких случаев когда-то и появился user-agent-сниффинг.

Если дело дошло до починки конкретного движка, есть аварийный приём — проверка свойства, которое есть только в WebKit:

```scss
@supports (-webkit-hyphens: none) {
	// правило применится только в Safari
}
```

Это всё ещё определение браузера со всеми его минусами, поэтому прибегать к нему стоит в последнюю очередь и с комментарием, какой именно баг он обходит.
