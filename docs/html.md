# HTML и именование классов

## HTML

### Система HTML-чанков

В шаблоне работает система чанков на основе пакета `gulp-file-include`, благодаря которому можно разделять HTML-файлы на блоки.  
Все чанки находятся в папке `html/chunks/`. Здесь есть основные стартовые чанки *(head, header, footer, modals и тд)*, которые уже подключены к стартовой странице. Помимо основных чанков, сюда вы можете добавлять свои собственные и вызывать их в любом месте страницы с помощью конструкции `@@include('../chunks/header.html')` (это пример для страницы внутри папки `pages`).  
Также есть возможность передавать параметры внутрь чанков, чтобы переиспользовать их в разных местах или страницах. Вот пример конструкции с передаваемым параметром `title` - `@@include('../chunks/head.html', {title: 'Главная страница'})`, при этом, внутри файла `head.html` должен быть указан параметр `@@title`, на место которого будет вставлен заголовок.  
Это не все возможности пакета `gulp-file-include`, но они наиболее часто используемые, если хотите узнать больше - [вот ссылка на репозиторий](https://github.com/haoxins/gulp-file-include).

### <h3 id="html-head">Мета-теги страницы</h3>
Чанк `head.html` принимает два параметра: `title` и `description`.

	@@include('../chunks/head.html', {title: 'Каталог', description: 'Описание страницы для поиска и превью в соцсетях'})

`title` попадает в `<title>` и `og:title`, `description` — в `<meta name="description">` и `og:description`. Если `description` пустой или не передан, оба тега не выводятся.

Остальное в чанке общее для всех страниц:

| Тег | Что поправить в форке |
| :--- | :--- |
| `theme-color` для светлой и тёмной схемы | цвета фона из `base/colors.scss` |
| `favicon.svg` и `apple-touch-icon.png` (180×180, непрозрачный фон) | файлы в `src/root/` |
| `preload` основного шрифта | имя `.woff2`, если сменился шрифт в `base/fonts.scss` |
| `og:locale` | язык сайта |

`og:image` и `og:url` требуют абсолютного адреса сайта, поэтому добавляются в форке, когда известен домен.

`<h1>` пишется в контенте страницы — у каждой страницы свой заголовок. Название сайта в шапке размечается обычным текстом или ссылкой на главную.

### <h3 id="html-a11y">Доступность разметки</h3>
Чанки и сниппеты шаблона уже размечены так, чтобы страницу можно было пройти с клавиатуры и прочитать скринридером. Придерживайтесь тех же правил в своей вёрстке — форк унаследует их во все проекты.

**Кнопке нужен `type`.** По умолчанию `<button>` имеет тип `submit` и внутри формы отправляет её:

	<button type="button" class="modal-link button" data-modal-open="callback">

Исключение — кнопка закрытия внутри `<form method="dialog">`: там нужен именно `submit`, он и закрывает окно.

**Кнопке нужна подпись.** Если внутри только иконка, текста для скринридера нет — добавьте `aria-label`:

	<button type="button" class="notify__close" aria-label="Закрыть" popovertarget="addToCart" popovertargetaction="hide">

**Иконки спрайта прячутся от скринридера.** Они дублируют текст рядом или подпись кнопки, поэтому читать их не нужно. `focusable="false"` убирает иконку из обхода по `Tab`:

	<svg aria-hidden="true" focusable="false" class="icon" width="24" height="24"><use href="img/sprite.svg#close"></use></svg>

Сниппет `svg` вставляет заготовку сразу с этими атрибутами.

**Элемент, который раскрывает что-то, сообщает об этом.** Бургер и другие кнопки открытия окна с атрибутом `aria-expanded` получают его актуальное значение от модуля модальных окон при открытии и закрытии.

**Скрытое должно быть скрыто по-настоящему.** `opacity: 0` и увод за экран оставляют ссылки и кнопки доступными для `Tab` и видимыми для скринридера. Для скрытия используйте `display`, `visibility` или нативные состояния `<dialog>` и `popover` — так сделаны модалки, боковое меню, оповещения, подменю и тултипы. Если элемент нужно спрятать только визуально, оставив его для скринридера, есть класс `sem-hide`.


## Именование классов
Общий подход в организации структуры и именование классов я делаю по БЭМ. Есть некоторые "монолитные классы", которые зафиксированы в каждом проекте и не меняются в связи со своей универсальностью. Также есть некоторые кастомные именования, которые продиктованы логикой шаблона.  

### Базовая структура страницы
Пример базовой структуры страницы, которая кочует от проекта к проекту и не меняется *(как раз тут используются монолитные классы)*:

	<body class="page"> --> для body всегда класс 'page'
		<div class="wrapper"> --> внутри body обертка с классом 'wrapper', всегда ее использую, помогает реализовать неожиданные дизайнерские запросы
			<header class="header"> --> для header всегда класс 'header'
				<div class="container"></div> --> внутри header ограничивающий контейнер с компонентом 'container'
			</header>
			<main class="content"> --> для main всегда класс 'content', на котором завязано многое далее по дереву
				<section class="content__block"> --> каждый уникальный раздел/блок страницы всегда с тегом section и классом-элементом 'content__block'
					<div class="container"> --> внутри раздела/блока всегда ограничивающий контейнер с компонентом 'container'
						<div class="custom-block"></div> --> тут уже можем встраивать структуру конкретного раздела/блока с уникальными классами
					</div>
				</section>
			</main>
			<footer class="footer"> --> для footer всегда класс 'footer'
				<div class="container"></div> --> внутри footer ограничивающий контейнер с компонентом 'container'
			</footer>
		</div>
	</body>

*Раньше я начинал разметку конкретных блоков прямо с тега `section`, типа `.content__block.custom-block ➔ .custom-block__container ➔ .custom-block__body` и тд, но отказался от такого подхода, так как он изначально заставляет вас создавать кучу пустых и не нужных классов. Теперь уникальные блоки начинаются внутри ограничивающего контейнера. А если необходимо изменить к примеру контейнер, можно обратиться к нему через селектор `:has`.*

### Примечания по некоторым монолитным классам
Большинство монолитных классов расположены в файле `src/scss/layout/base.scss`. Обязательно ознакомьтесь с этим файлом, чтобы понимать логику структуры выше.

`container` — ограничивающий контейнер: задаёт ширину, центрирование и боковые отступы.

	<div class="container">

Появление при прокрутке — отдельный компонент `appear`, он ставится туда, где анимация нужна:

	<div class="container appear">

Анимация построена на `animation-timeline: view()` и целиком отключается у посетителей с `prefers-reduced-motion: reduce`.

### <h3 id="component-api">Подключение встроенных компонентов (data-атрибуты)</h3>
Встроенные компоненты шаблона подключаются data-атрибутами: `data-tabs`, `data-slider`, `data-modal`, `data-spoiler` и тд.

	<div class="tabs" data-tabs>

Один и тот же атрибут делает две вещи: по нему скрипт находит компонент на странице и по нему же работают технические стили. Классы остаются целиком в вашем распоряжении — они нужны только для оформления и живут по правилам БЭМ. Класс можно переименовать под дизайн: поведение компонента от него не зависит. Исключение — [навигация](scss.md#navigation-component): её модуль и технические стили работают по БЭМ-классам `navigation__*`.

#### Как устроен атрибут компонента
Корень компонента — атрибут во множественном числе или по имени компонента, его части — тот же префикс с уточнением:

	<div class="tabs" data-tabs>
		<div class="tabs__link-list">
			<button type="button" class="tabs__link" data-tab-link>Таб 1</button>
		</div>
		<div class="tabs__content-list" data-tab-panels>
			<div class="tabs__content" data-tab-panel>Контент 1</div>
		</div>
	</div>

Режимы работы компонента задаются значением корневого атрибута:

	<div class="tabs" data-tabs="empty">

Значений можно указать несколько через пробел — стили ищут их селектором `[data-tabs~="empty"]`.

Атрибут со значением-идентификатором связывает элементы между собой: `data-modal-open="callback"` открывает окно `<dialog id="callback" data-modal>`, а `data-slider="example"` задаёт имя слайдера, к которому обращаются настройки Swiper.

#### Свои компоненты
Для собственных компонентов проекта используйте такую же схему: атрибут `data-<имя>` для корня, `data-<имя>-<часть>` для частей. Как подключить свой модуль к реестру — в разделе [Реестр модулей и ленивая загрузка](js.md#module-registry).

### <h3 id="component-states">Состояния компонентов</h3>
Состояние — это то, что меняется во время работы страницы: окно открыто, таб выбран, поле заполнено, страница прокручена.

**Сначала берите то, что браузер знает сам.** У нативных элементов состояние уже есть, и его видно в CSS без единой строчки JS:

| Селектор | Состояние |
| :--- | :--- |
| `dialog[open]` | модальное окно открыто |
| `details[open]` | спойлер раскрыт |
| `:popover-open` | оповещение показано |
| `:checked` | чекбокс или радио отмечены |
| `:placeholder-shown` | в поле ничего не введено |
| `:user-valid` / `:user-invalid` | поле прошло или не прошло проверку *(только после ввода)* |
| `:disabled` | элемент выключен |

**Дальше — ARIA.** Когда состояние нужно и стилям, и скринридеру, оно находится в ARIA-атрибуте, и стили читают тот же атрибут. Так внешний вид и доступность не могут разойтись:

| Атрибут | Где используется в шаблоне |
| :--- | :--- |
| `aria-selected="true"` | активная ссылка табов |
| `aria-expanded="true"` | бургер и кнопки открытия окна, пока окно открыто |
| `aria-current="location"` | пункт оглавления статьи, до которого долистал посетитель |

	.tabs__link[aria-selected="true"] {
		background-color: var(--c-main);
	}

**Всё остальное — в `data-state`.** Значения разделяются пробелом, селектор — `[data-state~="fill"]`:

	<div class="form__field" data-state="fill">
	<body data-state="load-dom load scroll">

	.form__field[data-state~="fill"] {
		border-color: var(--c-main);
	}

Из JS состояние ставится утилитой `setState` — она добавляет и убирает отдельное значение, не затирая остальные:

	import setState from '../utils/setState.js';

	setState(field, 'fill', Boolean(input.value));

Состояния, которые шаблон ставит на `<body>`: `load-dom`, `load` *(модуль [detectPageLoad](js.md#detectPageLoad))*, `scroll` *([detectPageScroll](js.md#detectPageScroll))*, `lock`, `lock-clear` и `lock-<имя окна>` *(модуль [pageLock](js.md#раздел-1-технические-модули))*.
